## Test session 2: what broke and why
### Retry crash (fixed, `8e412c3`)
`coop_results restart` on the host ran the game's `Restart` (sv_restart): the same-map load in place. With the lifecycle same-map cleanup (`0xf8f0(0)`) the still-open fail menu then faulted: the game's own "EXCEPTION" dialog (class `#32770`, found with a window list; the log just stopped) read `Access violation ... reading 0x3f7e7c0a at 0xdba8db ... caught in function cGuiManager::Update<-MOD_UpdateGameMenu<-cGameApp::HostFrame`. The main thread then waits in the dialog (CPU 0, "Responding"). Fix: `OnNative` takes `Restart` / `RestartMission` on the host (or offline) itself: `ClearHudMenuCode`, `closegamemenu`, `coop::HostRestartNow()` (F5's hop without the second press; `coop.cpp`, +20 lines, lead's file). `[Flow] RetryViaMenu=0` restores the in-place restart. `tools-src/stack-scan.ps1` is a raw stack scan of a hung game thread (Wow64 context); the dialog text is the faster tell.

### The mission table interleaves hunt maps
`GameDll+0x1653b8`, 28 entries of 0x14 bytes (byte 0 = number, name at +1, movie type at +0xb), printed by `coop_flow`:
`0 map1, 1 map2a, 2 map2b, 3 map2c, 4 huntmap3, 5 map3a, 6 map3b, 7 map3c, 8 map4a, 9 map4b, 10 map5, 11 huntmap1, 12 map6, 13 map7, 14 map8, 15 map9, 16 huntmap2, 17 map10, 18 huntmap4, 19 map11a, 20 map11b, 21 map11c, 22 map12a, 23 map12b, 24 map12c, 25 maptsavo, 26 mapisland, 27 maparena` (type 1 = `Movies\i<map>` plays before it, 2 = `Movies\o<map>` after it: map1, map2a, map3a, map4a, map5, map6, map7, map8, map11a, map12c are type 1; map12a is type 2). So a story run is MAP2C -> HUNTMAP3 -> MAP3A, MAP5 -> HUNTMAP1 -> MAP6, MAP9 -> HUNTMAP2 -> MAP10 -> HUNTMAP4 -> MAP11A. The earlier notes (and `NextStoryMap` for F6, which skips hunts on purpose) assumed 21 story maps in a row. The hunt success menu (`CM_NEXT_MISSION`, `MISSION_TYPE_HUNT`) opens a modal "hunt again or skip hunting" (`guiHuntActionOption`, GUIRENDEROPTIONS.SCR ~1960) before the autosave modal; its result is `GameLoadHunt` (hooked: host decides) or `SkipHunting()` + `GameLoadLevel`.

### mod_spmap needs a lower-case name (fixed, `9a1aecb`)
`0xa800` (the profile step of `mod_spmap`) compares against the lower-case table: the host's restart hop sent `mod_spmap HUNTMAP3` and left its profile on map1 (index 0) while the client, which lower-cases, was right (index 4). Story maps hid it (the map-load sync repairs them); a hunt map has no sync. `coop.cpp` now sends the lower-case name from the restart hop and from F6.
