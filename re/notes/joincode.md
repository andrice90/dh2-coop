# Join code: friends join the host's tailnet with one pasted code (joincode job, 2026-10-18)

Branch `joincode` in `D:\scary hunt\dh2coop-truck` (from main `93c7b1f`). Port 27650 for the runs. Nothing here touched this PC's real Tailscale state, firewall, clipboard or browser (see "Tested" and "Cannot be tested").

## What was built

**1. Join code** (`mod/src/coop/joincode.{h,cpp}`, pure functions; PowerShell twin in `tools-src/kit/install.ps1`)
- `DH2-` + base64url (no padding) of ASCII `v1|<ipv4>|<port>|<authkey or empty>|<host name>`.
- Decode rejects: IPv4 outside 100.64.0.0/10 (or not canonical dotted quad), port outside 1..65535 (leading zeros, text), key not `^tskey-auth-[A-Za-z0-9-]+$`, name > 32 chars or not printable ASCII (`|` splits fields), wrong field count, unknown version, base64 padding / `+` `/` / length 1 mod 4 / non-zero trailing bits, total > 300 chars. Whitespace anywhere is ignored (chat wrapping); the `DH2-` prefix is case-insensitive.
- `MaskKey` (`tskey-auth-kTE…`), `Describe`, `MaskedCode` (`DH2-…(key hidden)` / `DH2-…(no key)`), `RedactSecrets` (masks `tskey-…` and `DH2-…` runs in a text line).

**2. Host lobby** (`mod/src/coop/lobby_invite.cpp`, `clipboard.{h,cpp}`, `coop.h`, `ui/overlay_module.cpp`)
- HOST section: masked "Friend key" field with Save (Enter also saves) and Remove; stored as base64 of a `CryptProtectData` blob (current user, `CRYPTPROTECT_UI_FORBIDDEN`) in `dh2coop-lobby.ini` `[Lobby] FriendKey`; read back through DPAPI right after saving; the log only says `friend key saved (N chars)`.
- "Copy join code": tailnet IP + host port (the port field, or the hosting port) + saved key + player name -> CF_UNICODETEXT. Disabled with a yellow hint when there is no tailnet IP; without a saved key it copies an IP-only code and says "for friends already on your tailnet". Also shown while hosting (next to the existing IP "Copy").
- "Tailscale setup help": copies the ACL snippet (host tailnet IP and port filled in, `<HOST_TAILNET_IP>` if there is none), then ShellExecutes `https://login.tailscale.com/admin/acls/file` and `.../admin/settings/keys`, and shows the steps (replaces the default allow-all policy; merge by hand if you have rules; reusable + ephemeral + `tag:dh2friend` + 90 days).
- Console twins: `coop_friendkey <key>|clear`, `coop_joincode show|file` (file writes the whole code to `<log dir>\dh2coop-joincode.txt`), `coop_joinfield <code|ip|file>` (feeds the overlay exactly like a paste; `file` reads the file above, a console line holds only 127 chars), `coop_tshelp file` (ACL snippet to `dh2coop-acl.txt`, no browser, no clipboard), `coop_lobby <join code>` (decode, then join).
- Test knob: `[Coop] TestTailnetIp=100.x.y.z` (or `none`) in `dh2coop.ini` pretends this PC's tailnet address (run with `-Set 'Coop.TestTailnetIp=100.101.102.103'`).
- `console::Exec` and the command-file log now run lines through `RedactSecrets` (before this, `console::Exec('coop_friendkey <whole key>')` was logged in full; found in the first run, fixed, old logs deleted).

**3. Client lobby** (`overlay_module.cpp`): the Host IP field takes a pasted join code (ImGui `CallbackEdit` rewrites the text) and swaps it for the IP, sets the port, shows "Join code accepted (host NAME): ip, port N. Press JOIN." in blue; a damaged code shows why in red. JOIN also resolves an unswapped code. The key in the code is dropped (never stored by the client).

**4. Installer** (`tools-src/kit/install.ps1`, `install.bat`, `README.txt`, `NOTE.md`): everything it did before, plus, in order: one UAC elevation (questions first in the original window; the join code reaches the elevated copy through a temp file, not the command line; `-DryRun` does not elevate) -> `-JoinCode <code>` or the prompt "Paste the join code from your host (press Enter if you are the host)" (3 tries) -> Tailscale (detect `C:\Program Files\Tailscale\tailscale.exe`, else `winget install --id Tailscale.Tailscale -e --silent --accept-package-agreements --accept-source-agreements`, else open the download page and wait for Enter, 3 tries) -> friend with key: skip when Running and `tailscale ping -c 1 --timeout 5s <host>` answers; signed in elsewhere or stopped: explain, Y/N, `tailscale login --auth-key=<key> --unattended --hostname=dh2-<name>` (says `tailscale switch` goes back); signed out: `tailscale up --auth-key=<key> --unattended --hostname=dh2-<name>`; then waits up to 60 s for Running and prints host reachability -> host: `tailscale up --unattended` when signed out (polls status up to 5 min, opens `AuthURL` once through explorer.exe), prints the tailnet IP, the ACL snippet and the key steps, offers (Y/N) to copy the policy and open both pages -> firewall rule `DH2 coop (Tailscale)` (replaced: inbound, `Main7.exe`, UDP, RemoteAddress 100.64.0.0/10, Allow, all profiles; warns when an enabled inbound Block rule for the game exists) -> lobby prefill `JoinHost`/`JoinPort` (game Bin, or `%LOCALAPPDATA%\dh2coop` under Program Files, the `core::log_dir()` rule; the parent passes the path so an admin account's LOCALAPPDATA is never used) -> summary. An IP-only code: friend signs in (`tailscale up --unattended`) to an account the host invited.
- `-Uninstall` also removes the rule, the lobby ini (it holds the key blob) and the test files; says Tailscale stays installed. `-DryRun` prints every Tailscale / winget / firewall action (the files are still copied; status reads stay real). New switches: `-IAmHost`, `-Yes`, `-Simulate <json>` (tests, implies -DryRun), `-SelfTest`. Keys and codes are masked in everything printed (Tailscale's own error text goes through `Hide-Secrets` too).
- README.txt: install, network (host once / host every time / friend), play and "if join does not connect" rewritten, plain and short.

## Decisions / things for the user and the lead

1. The ACL snippet replaces the host's whole policy file (the default allow-all). The lobby help and the installer both say so; a host with custom rules must merge by hand. Confirm this is the intended UX.
2. The host's friend key is a reusable 90-day secret; the join code carries it in clear base64url (anyone with the code can join the tailnet as `tag:dh2friend`, limited to the game port by the ACL). Say so to friends ("send it only to friends"; the lobby message says it).
3. Windows firewall rule is now Tailscale-only (`100.64.0.0/10`): a host that used to play over the LAN (or another VPN) needs Tailscale for those friends too, or Windows' own "Main7.exe" prompt rule.
4. `tailscale up --auth-key=<key>` puts the key on the tailscale.exe command line for a moment (visible to admin-level processes); `--auth-key=file:<path>` would avoid it but needs a Tailscale from 2024 or later. Kept the brief's form; switch if you prefer.
5. `coop_joincode` needs an argument (`show` or `file`): the engine does not call a console command registered with a string parameter when it is typed without one (`debug.log`: "invalid number of parameters (0)"). The brief's bare `coop_joincode` cannot exist as written without a second command name.
6. Kit rebuild: copy `tools-src\kit\*`, `mod\build\dh2coop.asi`, `mod\dh2coop.ini`, `dinput8.dll`; `tools-src\kit-test` stays out of the kit. Friends need the new kit (the join code format `v1` is only in this build).
7. Observed once: right after the first `-Lobby` launch both of my windows closed by themselves within ~20 s (gracefully: the engine log shows a normal shutdown), and the game from the user's original install that had been running was gone at the next check; the second launch stayed up. Not caused by this change as far as I can tell (maybe another agent's or the user's cleanup). Noting it in case it recurs.

## Proposed MEMORY facts

Commands that need a bare form must be registered with `AddCommand0`.
- VERIFIED: console lines through `console::Exec` and the command file are 127 chars at most (existing fact), so a join code with a real ~63-char auth key (~166 chars) cannot be fed through `coop_lobby` / `coop_joinfield` in one line; `coop_joincode file` + `coop_joinfield file` is the long-code test path.
