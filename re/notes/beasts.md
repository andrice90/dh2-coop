### The crash class (MAP8 croc, MAP7 tiger, MAP4A lioness, MAP12C yeti)
`animals.cpp` thaws a client mirror's brain while the host's state is `CutScene` (it exists for scripted cutscenes that `WaitForTask` on an animal). But the host's animal is also in `CutScene` during every sync attack on a player or NPC. The thawed copy runs its own brain and starts its own attack ring with whatever local body it picks (the local hunter, the host's puppet, Reginald). The host's attack ends, the copy is frozen again, the ring stays. The next clip its legs script plays (`run`, `idleattack1`) is forwarded to the linked part, which lacks it, and `cModelPart::SetAnim(int,float,float)` (EngineDll7 `0x1e73b0`) raises `Could not forward animation %s from %s to %s model %s` (arguments: clip, this part's name, the partner's name, this part's owner model; read from the decompile). Raised under `GotoState` (the mirror's guarded `SetBodyState`) it is a caught log line; raised under `cModelPart::Update` (the croc's legs script) it is the modal EXCEPTION dialog and then an access violation. `MirrorStateOk` cannot cover the Update path.

Fix: `beasts::NoCutSceneThaw(ent)`. Water crocodiles never thaw. Any other animal thaws only while this process's camera is on a cutscene rail (`LocalPlayer().viewPos` more than 4 m from the hunter, the test of `story.cpp PlayerInCutscene`), `[Animals] ThawNeedsCamera=1` (0 = the old rule for non-crocs). A frozen copy in `CutScene` keeps the animal's last pose while the host's animal and the victim play the attack; the victim's reaction still arrives as `kPlayerHurt` / `kPlayerKnock`. UNVERIFIED on cutscene maps whose scripts wait on an animal (MAP6 cs3 bear, MAP4B cs5-7, MAP8 cs4/cs5): nobody has run them with the key on. MAP12C opening behaves the same with the key on and off (the client waits in `defer host fire 'cScrTask01' until the local cutscene camera ends` for 80+ s either way; not caused by this).

### CobraBitesNearest: decision 1
MAP7, run with `-Set Animals.CobraBitesNearest=1`: host 9 m or more away, client 1.1 m from the cobra: host `animals: cobra id=239 bite target -> puppet (player 1, 1.1 m)`; every 2.5 s host `combat: animal id 239 hurt player 1 for 0.0 (type 3)`, client `took 0.0 from animal id 239 (type 3)`; the client HUD shows the poison icon and the green overlay (`beasts-map7-cobra2-game2.png`). With the key off (run 1) the cobra struck once at the host's spawn target (9 m away) and the client 1.1 m from it was never hurt. No fault in either run; the client's dart and bullet deaths work with the key on; the default build logs `cobra bites nearest=true` and the same `-> puppet` line. Puppets are parked, not destroyed (`park_puppet`), so `+0x728` never dangles when a player leaves. `AimCobras` also skipped parked cobras now (it aimed an unspawned cobra at the nearer of two players 17000 m away and logged each flip).
