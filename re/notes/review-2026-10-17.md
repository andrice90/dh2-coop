## High

### H1 — Recycled animals stay dead on clients; their later deaths are never committed (VERIFIED)
- **Where:** host `animals.cpp:659-663` (`announced_.insert(uid).second` gates `Commit(kAnimalDied, uid, ...)`), `events.cpp:521-527` (`FindJournal(kind, subject, key)` drops any repeat). Client `animals.cpp:929-933`: once `death_presented`, the mirror pins hp 0 and `continue`s every frame, with no placement, no state, no hit reports. `:1001-1009` does the same through `dead_`. `:1133-1136` releases the brain after the death (`UnfreezeDead=1`).
- **Engine fact:** story scripts recycle a dead animal (same entity) with `CanBeRespawned()` + `MoveToPos` + `StartTask` (TRIGGERMISSION02A/02B/02C/05/08, MAPARENA/MAPISLAND/MAPTSAVO WORLD.SCR, HUNTMAPBASE predator). MAP2B's `SpawnWolves` keeps spawning from 3 wolf entities until a counter passes 9. **Log proof** (two-PC host log, MAP2B): `death commit id=173` 12:03:51, `id=172` 12:04:34, `id=171` 12:05:25. Then the sync lines show 171/172/173 back at hp 50 (12:06:00), and 172 hunting again (`IdleSurprise` at a new spot, hp 80, 12:06:18).
- **Failure:** on a client, each wolf is presented dead once. From then on its mirror ignores the host:
  - The respawned host wolf is invisible to the client (its mirror stays a corpse, or vanishes when the host parks it at -10000).
  - The host wolf still attacks the client's puppet. `combat` forwards `kPlayerHurt`/`kPlayerKnock`, so the client is mauled by an animal it cannot see or shoot: the hit report is skipped once `death_presented`.
  - The client's own replayed trigger script may also "respawn" its local copy, whose brain was already unfrozen. That copy runs local AI with its health pinned at 0.
  - The second death on the host is never committed: `announced_` and the journal both drop it.
  - A late joiner replays the *first* death and pins a living wolf as a corpse.
- **Maps:** MAP2A, MAP2B (Hugh's wolf defence), MAP2C, MAP5, MAP8 (scrub bull waves), the bonus maps, and the hunt-map predator.
- **Confidence:** high. The recycling is in the log; the client behavior is in the code.
- **Fix sketch:**
  - Commit one death per *life*: keep a per-id life counter on the host. Bump it when hp goes from ≤0 back to >0 (or when the death flag clears). Put it in `i0` and include it in the dedup (`FindJournal` must compare `i0` for `kAnimalDied`).
  - Add a `kAnimalRevive` commit, or let the client react to a snapshot with hp>0 for a `death_presented` mirror: clear `death_presented`/`dead_`, freeze the brain again, `SetBodyState(sample.state, true)`, and resume placement.
  - Replace `announced_` with "last committed life".

### H2 — Networking pumped only from Present; fullscreen alt-tab drops the session (VERIFIED engine, CODE effect)
- **Where:** `coop.cpp:381` (`g_session.Service()` runs only in `CoopModule::OnFrame`). `OnFrame` is dispatched only from the `IDirect3DDevice8::Present` detour (`d3d8_hooks.cpp:130-168`). No `enet_peer_timeout` anywhere, so ENet's defaults apply (`enet.h:230-233`: limit 32, minimum 5000 ms, maximum 30000 ms).
- **Engine fact (Ghidra slot E):** `cRenderDX::Flip` (EngineDll7 `0x354c40`) calls `TestCooperativeLevel` (device vt `+0xc`) and only calls `Present` (vt `+0x3c`) when it returns 0. `BeginFrame` (`0x3549d0`) has the same gate.
  - With a lost device, nothing reaches our hook: no `OnFrame`, no `Service`, no state sends. A fullscreen D3D8 device is lost while alt-tabbed or minimized, and on the secure desktop.
  - `AllowBackground=1` keeps the simulation running, but not `Present`.
- **Failure:** the kit starts the game **fullscreen** (no `console.cfg`; `docs/mod-learnings.md` "Windowed mode").
  - A friend alt-tabs for more than ~5 s (Discord, the firewall prompt). The other side gets no acks for its ENet pings and reliable sends, and times them out.
  - If the host alt-tabs, every client drops. AutoRole=join then rejoins and replays the journal (M6).
  - A window drag in windowed mode stops frames the same way (Win32 modal loop).
- **Confidence:** high for the gate; medium that friends hit it often (they will).
- **Fix sketch:**
  - Pump the session (and `animals::HostTick`, `events::Pump`) from a main-thread hook that runs every frame whether or not a frame is presented: `cRenderDX::Flip` itself, before its `TestCooperativeLevel`, or Main7's per-frame `FUN_0040f170`. Keep the world-touching work behind `LocalPlayer().valid` as now.
  - Raise the timeouts: `enet_peer_timeout(peer, 0, 30000, 90000)` on both sides after connect.
  - Optionally send an "away" flag so the host skips that puppet as a target while its owner is not rendering.

### H3 — No mod build / protocol check (VERIFIED)
- **Where:** `protocol.h:16-17` (`kProtocolVersion = 1`, `kGameBuild = 434`). `session.cpp:292` rejects only when those two *constants* differ, so any two builds of the mod pass.
- **History:** `git log -p` shows the protocol at version 1 since `2838c21`. AnimalStates gained the `arms` string in `28cb014` without a bump. Weapon kinds 5/6, flag bits, and GameEvent kinds 7–16 (`kPropAnim`, `kPlaySA`, `kSyncRequest`/`kSyncDone`, `kCutsceneSkip`, combat, `kPropHit`) came later.
- **Failure:** two friends on different kits connect normally.
  - Every AnimalStates fails `Decode` on the older side, and `session.cpp:520-524` logs `net: drop malformed packet` 20 times a second, each flushed.
  - An old client never sends `kSyncRequest`, so the host never adds it to `g_synced`. It then gets no live commits at all, only `kMapStart`.
  - Unknown kinds are logged once and ignored. The story silently diverges.
  - The README asks for "the same kit", but nothing enforces it.
- **Confidence:** high.
- **Fix sketch:**
  - Bump `kProtocolVersion` to 2 now. Bump it on every wire or semantic change: event kinds, flag meanings, field layout.
  - Add a 32-bit mod build id to Hello (git short hash or build timestamp, compiled in) and reject on mismatch with `VersionMismatch`.
  - On the client, show the reject reason in the overlay ("host runs kit X, you run Y").
  - Rate-limit the malformed-packet warning per peer.

## Medium

### M1 — NPC death on a client: OnDie twice and an animal-brain write (CODE)
- **Where:** `animals.cpp`:
  - `:1034-1037` intends "dead NPC: let the NPC's own update die the NPC way" (`dead_.insert(id); continue;`).
  - On the next frame, `:1001` (`if (dead_.count(id) != 0)`) catches the NPC first and calls `PresentDeathOnce`.
  - `PresentDeathOnce` (`:1131`) calls entity vt `+0x154`. On `cObjNPC`/`cObjGuide` that is `cObjNPC::OnDie` (`0x5fde0`, `re/notes/npc-health.md` slot table).
  - Then `:1133-1134` calls `entity::FreezeBrain(ent, false)` = `cAIHuntBrain_Animal::FreezeBrain`. On an NPC that brain at `+0x200` is a `cAIBrain_NPC` (`entity_api.cpp:476-485`), so the call writes byte `+0x79` of the wrong class.
- **Failure:** the host's guide/companion dies (protect objective lost, or a scripted death).
  - The client runs `OnDie` from our call, and again from its own update when the profile health hits 0 (the comment at `:1026-1027` relies on that).
  - `cObjGuide` death writes mission fail code 6 itself (checklist pitfall), so the client's mission is written twice and its death state machine runs twice.
  - The brain write corrupts a field of `cAIBrain_NPC`.
- **Confidence:** high for the call sequence; the impact of the stray write is unknown.
- **Fix sketch:**
  - In the `dead_` branch at `:1001`, skip NPCs (`if (m.is_npc) { pin profile 0; continue; }`).
  - In `PresentDeathOnce`, never call `FreezeBrain` for `is_npc`.
  - Better: have `entity::FreezeBrain` check the brain vtable (CommonDll `cAIHuntBrain_Animal`) and refuse other classes.

### M2 — `Reset()` thaws NPC mirrors with the animal FreezeBrain (CODE)
- **Where:** `animals.cpp:804-808`. For every `m.frozen` mirror, including NPCs frozen with `CharacterBrainFreeze` at `:966`, it calls `entity::FreezeBrain(ent, false)`. That is the animal function on the NPC's `+0x200` brain.
- **Callers:**
  - The host leaving or timing out: `coop.cpp:503-508`.
  - `coop_leave` and a join/host restart: `coop.cpp:439-441`.
  - The host's last peer leaving (`SetSessionActive(false)`). The host has no mirrors, so nothing happens there.
- **Failure:** the host quits mid-map; the client carries on alone.
  - Its guides/companions stay `CharacterBrainFreeze`d for the rest of the map (escort/follow objectives cannot be done solo), and their brains get the stray `+0x79` write.
  - Cobra mirrors are thawed with the same call (on a cobra it faults; SEH catches it).
  - Cobras' `+0x728` bite pointer, cleared at `:985-991`, is never restored.
- **Confidence:** high.
- **Fix sketch:** `m.is_npc ? CharacterBrainFreeze(ent, false) : FreezeBrain(ent, false)`. Skip cobras for `FreezeBrain`, and store and restore their `+0x728`.

### M3 — Stale entity pointers for ≤1 s after mid-map removals (VERIFIED engine, CODE effect)
- **Engine facts (Ghidra slot E):**
  - `cObjManager::RemoveEntity(int id, int del)` (EngineDll7 `0xbd570`) with `del != 0` calls the entity's vt `+0x24` (destroy) **immediately** and nulls the slot.
  - `RemoveEntity(cObjEntity*, int)` (`0xbd6d0`) forwards by id.
  - `AddEntity(cObjEntity*)` (`0xbd4b0`) writes the array index into `+0x04`, so **id == index**.
- **Where:** `player_tracker.cpp:286` rebuilds `g_animal_list`, `g_npc_list` and `items_` once a second. Every module uses those pointers each frame.
  - Puppets use a `/npc/` model, so they are in `Npcs()`.
  - `OnRemoteLeft` (`puppets.cpp:719-729`) erases the puppet record and `RemoveEntity(..., 1)`s it. `Owns()` then returns false while the freed pointer stays in `Npcs()`.
- **Failure:** 3–4 players, one leaves.
  - **Host:** while other peers remain, `HostTick` (`animals.cpp:667-718`) treats the freed puppet as a world NPC: `safe_read` id/pos, then `BodyStateName`, `UpperBodyState` and `PartStateName`, which are virtual calls through freed memory (SEH-guarded, but a reused block can make them call valid-but-wrong code). It then broadcasts the puppet to the remaining clients as a `kNpc` entry for up to 20 snapshots.
  - **Clients:** `LogSync` (`SyncLog=1` is the default) makes the same calls on their own removed puppet.
  - **Weapon swaps:** WEAPON.SCR `Changeout` destroys the weapon entity on every weapon change (`Destroy()` in `End`). `items_` keeps that pointer and `PollActions` calls `cObjItemEx::GetCurrentState` on it (`player_tracker.cpp:487`).
- **Confidence:** high for the window; medium that it crashes (it depends on heap reuse).
- **Fix sketch:** since id == index, validate before every use: `arr[*(int16*)(ent+4)] == ent`. One O(1) check in `Animals()`, `Npcs()` and the `items_` loop. Or rescan right after our own `RemoveEntity` and on a hooked `RemoveEntity(int,int)`.

### M4 — The puppet-removal AV is not harmless (VERIFIED symptom, UNVERIFIED cause)
- **Evidence:** `re/notes/coop-local/map12c-host.log:232-233` (2026-10-16 22:08:23, on leave). `first-chance exception 0xc0000005 at <unknown>+0x616d7548 eip=0x616d7548`, right before `UnlinkPart ... tag='BipLHand' -> -1`.
  - `0x616d7548` lies in no module and is the bytes `48 75 6d 61`, ASCII **"Huma"**.
  - The CPU executed a "pointer" read from memory that now holds text. The hand controller's sync ring (`ctrl+0x100` link → weapon part), or the model behind it, was freed and reused **before** the leave.
  - STATUS (Drop-out row) calls this AV harmless. The SEH guard in `guarded_unlink_part` (`entity_api.cpp:205-220`) only hides it, and `drop_weapon` then `RemoveEntity`s the weapon (`puppets.cpp:376-379`), with the ring possibly half-unthreaded.
- **Candidate cause:** each remote weapon change runs `drop_weapon` (`UnlinkPart`, then `RemoveEntity(weapon)`) and builds a new weapon and link. If `SetSyncWith(nullptr)` does not clear the weapon part's back link, the old weapon's freed link stays threaded into the hand ring. The current logs show `hand+0x100 before` non-null at most `LinkPart`s (10 of 12).
- **Confidence:** high that memory was corrupted; low on the root cause. The log predates Physics=1 and combat.
- **Fix sketch:**
  - Reproduce: client switches weapons about 20 times, then `coop_leave`. Log the full ring before each unlink.
  - Validate the link owners (`link+4`) against `EntityById` before calling `SetSyncWith`.
  - Prefer never deleting puppet entities mid-map: hide them (`+0xC0` bit 0), unlink them from the BSP, park them at -10000, take them off the attack list, and let the world teardown delete them. That also removes M3's puppet case.

### M5 — Journal dedup drops legitimate repeats (CODE)
- **Where:**
  - `events.cpp:152-158`, `:521-527`: a commit with the same (kind, subject, key) as *any* earlier journal entry is not sent.
  - `story.cpp:545-546` (PlaySA) and `:594-597` (prop anim) only skip the *last* value per id, so A→B→A passes the local check, but the third commit (A) is then dropped by the journal.
  - `story.cpp:383-387` / `:469` (`g_ran_fire`): a trigger fires once per id per map on clients.
- **Failure:**
  - A prop (gate, trap, door) that toggles open→closed→open stays closed on clients.
  - A late joiner replays A then B and ends on B while the host shows A.
  - A character that plays the same paired anim twice plays it once on clients.
  - A trigger the script re-arms and that fires again runs `OnActivate` only once on clients.
  - H1 is the animal instance of this.
- **Confidence:** high for the code. Which maps toggle props or re-fire triggers was not surveyed.
- **Fix sketch:** dedup only true one-shot kinds (`kTriggerEvent` arm, `kTrophyClaim`, `kPropHit`, `kMissionEnd` per code). For state kinds (`kPropAnim`, `kPlaySA`, fire with re-arm), journal every change with a sequence (`i0`) and either replay all, or keep only the last state per subject for catch-up.

### M6 — Rejoin on the same map replays non-idempotent commits (CODE)
- **Where:** a client timeout or disconnect (likely with H2) runs `coop.cpp:503-508`: `puppets::RemoveAll`, `animals::Reset` (clears `mirrors_` and `dead_`), `events::Reset` (`events.cpp:605-613`, clears `g_client_seen_map`). Story's `g_ran_fire` is **not** cleared (good).
  - AutoRole=join rejoins. The first `kMapStart` is "already loaded" (`events.cpp:261-268`), so `kSyncRequest` replays the whole journal.
- **Failure:**
  - `OnPlaySACommit` replays every paired anim: the MAP2A bridge mesh plays again, and `HoldCutscene` pins Hugh's pose until the host's state changes.
  - `OnPropAnimCommit` replays prop anims.
  - A finished `kMissionEnd` reopens the results screen.
  - Every dead animal gets a second `PresentDeath`, because the mirrors start fresh. On a cobra, vt `+0x154` counts the kill again.
- **Confidence:** medium-high.
- **Fix sketch:**
  - Send the client's last applied host serial and journal seq in `kSyncRequest`, and have the host replay from there.
  - Or keep a client-side "applied (kind, subject, key, seq)" set per map serial across a reconnect.
  - Mark already-dead local animals (hp 0) as `death_presented` without calling `+0x154`.

### M7 — New-map snapshots applied to the old map (CODE)
- **Where:** after a host map change, the first `OnFrame` runs `Service`, then `animals::HostTick` (new-map AnimalStates, channel 1, unreliable), then `events::Pump` (`kMapStart` commit, channel 2, reliable). See `coop.cpp:385-388` and `events.cpp:598-601`. The two channels are not ordered against each other.
  - On the client, `SameMapAsHost()` (`events.cpp:621-624`) is still true: the old host map equals the old local map, so the snapshot is applied.
  - It also returns true when no announcement has arrived yet (fresh join, `g_host_map` empty).
- **Failure:**
  - Client animals on the old map that share ids with new-map animals are frozen, teleported to new-map coordinates, and set to new-map states.
  - An entry that is dead or at hp 0 triggers `PresentDeath`, which runs `UpdateMissionStatus` on the client's old-map mission.
  - A fresh joiner's HUNTMAP4 deer (ids 120–124) mirror whatever the host sends for those ids until the sync request (needs a hunter, ≥1 s).
  - Usually brief: the follow load tears it down. It is still wrong-entity driving.
- **Confidence:** medium.
- **Fix sketch:** add the host map serial (u16) to AnimalStates (with the H3 bump), and drop snapshots whose serial is not the one the client followed or announced. Treat an empty `g_host_map` as "not the same map".

### M8 — Local script damage on mirrors becomes a hit; double death (CODE)
- **Where:** `animals.cpp:1015-1024` reports any local health drop below the host value as `AnimalHit`. The pinned hp is rewritten each frame, so only local changes show up.
  - Clients replay trigger `OnActivate`s and cutscenes. Those call `<animal>.Kill()` (story-inventory: 56 uses on MAP2B, 2C, 4B, 5, 6, 10, 12A; e.g. TRIGGERMISSION02B).
- **Failure:** the client's `Kill()` drops its mirror to 0.
  - An `AnimalHit` for the full health goes to the host. It kills the host's animal early if the host has not run that script yet, for example when the client applies a fire before the host's local copy reaches it.
  - The local `Kill` already presented the death. The host's `kAnimalDied` then calls `PresentDeathOnce`, which only knows its own flag, so the death is presented twice.
- **Confidence:** medium.
- **Fix sketch:** while `g_in_apply` (story) or inside a client cutscene, do not report hits. In `PresentDeathOnce`, skip `+0x154` when the local entity is already dead (`+0xC1` bit 2 / `Dead` state).

## Low

- **L1 `SetNpcProfileHealth` unvalidated write.** `animals.cpp:120-124` and `:1028`.
  - Every `/npc/` model entity (`player_tracker.cpp:330-335`) is mirrored as an NPC, and the client `memcpy`s into `*(ent+0x1F8)+0x54` (unguarded, in the pre-render hook).
  - Only `cObjNPC`/`cObjGuide` keep a `cProfile` there (npc-health.md). Another `/npc/` class (cutscene actor, corpse) gets a write into whatever `+0x1F8` holds, or an AV inside `hk_SetCamera`.
  - The host also reads garbage health for such entities, which can feed M1 (false dead).
  - Fix: check the vtable (cObjNPC `0x108270`, cObjGuide `0x108a50`) in `NpcProfileHealth`/`SetNpcProfileHealth`; fall back to `+0x19C`. UNVERIFIED that such entities exist (logs only show Hugh).
- **L2 Oversized unreliable becomes reliable.** In ENet 1.3.18 (`peer.c:136-143`), a packet larger than one fragment without `ENET_PACKET_FLAG_UNRELIABLE_FRAGMENT` goes out as **reliable** fragments.
  - A large AnimalStates (32 entries can reach about 2.8 KB) would then block `PlayerState` on channel 1 behind retransmits and count toward timeouts.
  - Current maps have ≤20 `AddAnimal`s, so it is probably under the MTU today.
  - Fix: set `UNRELIABLE_FRAGMENT` in `Send` for unreliable sends, or split snapshots.
- **L3 Unguarded `PlaySA` on commit.** `story.cpp:572-573` calls the engine body directly from `OnFrame` (events → handler). Every other commit path uses `__try`.
  - Under `/EHsc`, `catch(...)` in `modules::each` does not catch an SEH fault, so a bad partner or anim crashes the client.
  - Wrap it like `guarded_fire`.
- **L4 Stale `p.entity` across teardown.** `puppets.cpp:529-553` keeps `p.entity` until `OnMapLoaded` (`:512-523`).
  - The shutdown path reads freed puppets: `game4\Bin\dh2coop.log` 10:12:52 has four first-chance AVs in `safe_copy` on the second `StopServer`.
  - A `PlayerLeft`/`RemoveAll` in that window would `RemoveEntity` freed memory.
  - Null the pointers in `OnMapUnloading` and keep the buffers.
- **L5 Installer.**
  - (a) `install.ps1:161-162` copies the kit ini over the user's on every update and keeps only `PlayerName`; Port, AutoRole, overlay and puppet choices are lost. Merge keys instead, or keep user keys.
  - (b) Uninstall (`:124-125`) deletes `dh2coop-lastmap.txt`/`dh2coop-lasthost.txt` in Bin, but `host.bat`/`join.bat` store `%LOCALAPPDATA%\dh2coop\lastmap.txt`/`lasthost.txt`. Logs also live there, so the folder stays.
  - (c) No check that `Main7.exe` is closed: a running game locks `dinput8.dll`, and `Copy-Item` throws after the backup step.

## Looks wrong but is fine because …
- **No net thread.** `Session` has no thread. ENet is serviced only on the game thread (`OnFrame`), and every send happens there too, so there are no ENet or container races. The lifecycle thread only installs hooks and polls focus (atomics).
- **Packet parsing is robust.** Fixed-size messages need an exact length. AnimalStates and GameEvent bound the count and the string lengths before reading, and `ByteReader` fails closed and never reads past `len`. Unknown GameEvent kinds decode and are logged once. Ids are not spoofable: the host rewrites `PlayerState.playerId`, `AnimalHit.shooterId` and `GameEvent.actorId` from the peer, and drops client "commits".
- **Entity id reuse within a map does not happen:** `AddEntity` appends at `count` and reuses a slot only when the array is full (EngineDll7 `0xbd4b0`, slot E). BSP/script entities keep their ids for the map's life. The recycling in H1 is the *same* entity coming back.
- **Brain targets are ids.** `cAIHuntBrain_Animal::GetTarget` resolves `+0x254` through a lookup (`lead-p5-target.c`), so a removed puppet becomes a null target, not a dangling pointer. The `ProcessAttackStuck` detour is id-based too.
- **Calling conventions match** (checked against the mangled names):
  - fastcall members: `CharacterBrainFreeze`/`CharacterFreeze` (`QAI`) and `cHUDSlowMotion::Enable` (no stack args, per `lead-slowmo.md`).
  - All thiscall detours are declared `__fastcall(self, edx, ...)` with the right stack arguments (OnHurt ×3, PlaySA ×2, OnEndSA, SetAnim, mission message with `char` in a 4-byte slot, BspLoad, StartGame, StopServer, AddEntity, SetCamera).
  - cdecl: `ClaimCallback`, `SkipInput`, `FuncInflictDamage` (`KA` static), `AddStaticFuncf` (`QAA` varargs).
- **Mid hooks are correct.** In `combat.cpp` the sites are `cmp eax,1` right after `call [vt+0xFC]`: `eax` is the result, and `esi`/`ebx` are callee-saved and still hold the target. The relocated jcc is handled by safetyhook and was verified at runtime. In `npc_follow` the hook site `mov ebx,eax` sees the getter's `eax`, and `esi` is the brain.
- **No re-entry into our own detours:** every replay calls the trampoline (`Fire`, `Activate`, `ApplyMissionEnd`, `OnPlaySACommit`, claim). Nested script calls inside `OnActivate` are told apart by `g_in_apply`.
- **Teardown:** `OnMapUnloading` (from the `StopServer` hook) clears the tracker, animal and combat state before `DeleteAllObjects`. The pre-render callback is gated on `g_map_ready` and the main thread. The loading-screen thread's `Present` is skipped. Only mid-map removals are a problem (M3).
- **Map loads do not time out ENet:** `cBspTree::Load` plus `StartGame` took about 160 ms in the two-PC log (`map2a` 11:53:51.21 → .37). The real no-service windows are H2.
- **Journal growth is bounded:** capped at 1024 per map and cleared per map. The dedup keeps request floods from re-broadcasting (MAP12C fix). Live commits go only to synced clients, so a loading client gets everything in order through the catch-up.
- **No player-1-only code** (grep for id comparisons with 1). Player ids 1..3 come from `AllocId`; the overlay and snapshot arrays hold 4.
- **The console path is safe:** host map names are filtered to `[A-Z0-9_]` before `spmap`, and `copy_line` keeps lines under the engine's 0x80 slot.
- **`dinput` drain buffer:** `GetDeviceData` drains at most 32 items of 16–32 bytes into 1024 bytes.
- **Log volume:** the 33-minute two-PC host log is 2.3 MB, 18.7k lines (about 9/s), so per-line flushing is not a performance issue. (H3's malformed-packet spam would be.)
- **Foreign `dinput8.dll` backup:** `install.ps1:155-160` backs up once, only when the file is not the kit's (by hash). Uninstall removes only the kit's loader and puts the backup back. install → update → uninstall works.
- **A ghost puppet from a late `PlayerState` after `PlayerLeft`** needs network reordering: the host stops relaying when it handles the disconnect, so this is not a real issue.
- **Lead's `ad8b0b4` reviewed:**
  - The `EntityById(id) == self` guard in `hk_SetAnim`/`NotePlaySA` is correct, and the name read now happens after the guard.
  - `IsMirroredActor` still runs first and only does `safe_read`s.
  - The per-anim log set is bounded by the anim names.
  - `keep_engine_log` in DllMain runs after `set_self_module` and uses plain Win32 calls. `log_dir()` uses `std::filesystem` and `CopyFileW` under the loader lock, which works in practice for a plain file. If it ever deadlocks on some machine, move the copy to a dedicated early thread that waits on nothing.

## Proposed MEMORY facts
- `cObjManager::AddEntity(cObjEntity*)` (EngineDll7 `0xbd4b0`) stores the array index in entity `+0x04` and `+0xB4 = manager`, and appends at `count` (`+0x08`). It reuses the first null slot only when `count >= capacity` (`+0x0C`). So entity id == array index, and ids are not reused within a map until the array fills. Ghidra slot E, 2026-10-17.
- `cObjManager::RemoveEntity(int id, int del)` (`0xbd570`): with `del != 0` it calls the entity's vt `+0x24` at once (destroy) and nulls the slot. With `del == 0` it only unlinks (id `0xffff`, `+0xB4 = 0`, slot null). `RemoveEntity(cObjEntity*, int)` (`0xbd6d0`) forwards by id. `Set(int, ent)` (`0xbdb20`) destroys a previous occupant.
- `cRenderDX::Flip` (EngineDll7 `0x354c40`) and `BeginFrame` (`0x3549d0`) call `IDirect3DDevice8::TestCooperativeLevel` and skip `Present`/`BeginScene` while the device is lost. Nothing hooked on `Present` runs while a fullscreen game is alt-tabbed. Ghidra slot E, 2026-10-17.
- Story scripts recycle dead animals: `CanBeRespawned()` + `MoveToPos` + `StartTask` reuse the same entity (TRIGGERMISSION02A/02B/02C/05/08, MAPARENA/MAPISLAND/MAPTSAVO, HUNTMAPBASE predator). MAP2B wolves 171/172/173 died once each and came back with the same ids (two-PC host log 12:03:51–12:06:18).
- WEAPON.SCR `Changeout` destroys the weapon entity on every weapon change; SNAKE.SCR `Die` destroys ambient snakes. Hunter child item pointers are not stable across a weapon change.
- ENet 1.3.18 sends an unreliable packet larger than one fragment as *reliable* fragments unless `ENET_PACKET_FLAG_UNRELIABLE_FRAGMENT` is set (`peer.c:136`). Default peer timeout: 5 s minimum, 30 s maximum.
- Protocol: AnimalStates' `arms` string was added in `28cb014` without a `kProtocolVersion` bump. Version 1 covers several incompatible layouts.
