## Design requirements
1. **`net::Session`.** One class for both roles:
   - `StartHost(port, maxClients=3)`, `Join(host, port)`, `Disconnect()`
   - `Service()`: non-blocking, called once per game frame on the game thread; no threads of its own
   - `IsHost()`, `LocalPlayerId()`, `Peers()`
   - callbacks or an event queue for: connected, disconnected, timed out, and each message type
   - `enet_initialize` happens exactly once (this also covers the WSAStartup the game never calls)
   - default port **27420**; avoid the engine's dead 27318
2. **Channels.** 0 is reliable control, 1 is unreliable sequenced state, 2 is reliable events (for later: shots, damage, spawns).
3. **Protocol v1** (`net/protocol.h`):
   - a little-endian byte writer and reader with bounds checking
   - a message id enum
   - versioned `Hello{protoVersion, gameBuild=434, name[32]}` and `Welcome{playerId, hostTick, maxPlayers}`
   - `Reject{reason}`
   - `PlayerJoined{id, name}` / `PlayerLeft{id}`
   - `PlayerState{playerId, seq, tickMs, pos[3] float, yaw, pitch, velocity[3], flags(u16: crouch, prone, aiming, firing, dead), weaponId(u8), health(u8)}`
   - `Ping{t}` / `Pong{t}`
   - Host relays each client's `PlayerState` to other clients, so the topology is a star through the host.
   - Reject version mismatch, and reject a full lobby (max 4 players total).
   - Leave room for future `AnimalState`/`AnimalEvent`/`HitRequest`/`DamageEvent` ids. Reserve the ranges and document them, but do not implement them.
4. **Interpolation helper** (`net/interp.h`): a per-remote-player snapshot buffer (about 1 s), sampled at render time minus a configurable delay (default 100 ms), with linear position, shortest-arc yaw, and extrapolation capped at 250 ms. The game runs variable dt with `sv_fps` 100; `PlayerState` is sent at 20 Hz by default.
5. **Stats:** RTT, packet loss and bytes in/out per peer, exposed for a future overlay.
6. **Logging** through spdlog's default logger (the ASI configures it), at modest verbosity.

## Tests (`dh2net_test.exe`, exit code 0 on success)
- Serialization round-trip for every message, plus fuzz-ish truncated-buffer tests that must not crash or read out of bounds.
- In-process loopback: one host and 3 clients on 127.0.0.1. Check the handshake, ids 0..3, and `PlayerJoined` fan-out. Each client sends `PlayerState` at 20 Hz for 3 s, and every client must receive every other player's states via the host relay. Also test a 5th connection rejected (full), a version mismatch rejected, a client disconnect producing `PlayerLeft`, and a host shutdown producing disconnect events.
- Interpolation unit tests: a moving target gives a smooth output, and yaw wraps across ±180°.
- Print a summary table and run it twice to show it is deterministic enough.
